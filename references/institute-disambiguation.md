# 分身消歧：OpenAlex 中文作者碎片化

> OpenAlex 对中文作者的 author 实体**按署名形态拆分**，同一人有多个 author.id。
> 这是系统性问题，不是个别现象。

## 碎片化有多严重

大庆实例（2109 篇库）：

| 姓名 | author.id 数 |
|---|---|
| `Cheng Wang`（王成） | **13 个** |
| `Junhui Li`（李军辉） | 4 个 |

连**姓氏大小写**（`Junhui Li` vs `Junhui LI`）都能拆出独立分身。

**结论：任何按 author.id 聚合的中文机构名单，都系统性低估同一人产出。**
低估多少不知道——取决于门槛外还有几个分身没并进来。

## 合并三判据（缺一不可）

单一证据（仅姓名相同）会把**同名不同人**错并。三判据叠合才可并：

### 1. 合作者网络连通性（最重要）

查该姓名各分身的合作者共现（top 8~10）。如果几个分身共享**同一批枢纽合作者**，
大概率是同一人。

大庆例：`Junhui Li` 全库 **5 个** author.id，其中 3 个是真身
（合作者共现里都有**郑强、方菊晨、白雪峰**，三重共现），另 2 个是同名不同人。

### 2. 机构

各分身的 `raw_affiliation_strings` 是否都命中本院。同院 + 同枢纽合作者，几乎可判。

### 3. 主题一致性

代表作主题是否同一（古龙页岩油 / 三次采油 / 地震处理…）。
跨主题的分身要警惕——可能是同名不同人。

## 反证案例（为什么不能只看姓名）

大庆实例：还有 2 个 `Junhui Li` 分身（`A5124430829` / `A5133131670`），
主题是**奥陶系碳酸盐岩成岩 / 流体地球化学**，合作者是 Wei Wu / Bo Yan / You Zhang，
与古龙团队**零重叠**。

判定：**同名不同人，不并。**

这条反证必须写进名单——它是「仅凭姓名相同就合并」会出错的实证。
（这两个 ID 一度被误记为 `Cheng Wang` 的分身；脚本复核时按归一化姓名分组才发现
归属是 Junhui Li。**证据链里的 ID 归属也要复核**，不能只信旧记录。）

## 门槛外的分身什么情况下该并

门槛决定**谁进名单**，不决定**计数**——`yjy_papers` 的语义是「这个学者以院署名
发表的论文总数」。所以门槛外分身**不是一律不并**：

| 情形 | 处理 |
|---|---|
| 合作者**三重共现**（枢纽人物在 top5 里占 3 个以上）+ 主题完全一致 | **并入**（哪怕只有 1 篇） |
| 合作者**部分重叠**（top5 里 1-2 个相同） | **不并**，标下界 |
| 合作零重叠，主题完全不同 | 判**同名不同人** |
| 署名是缩写（如 `J Li`） | **不并**（缩写同名风险极高，证据太弱） |

大庆例：
- `A5126733539`（1 篇 2026 新文）合作者 top5 里白雪峰/方菊晨/郑强**三重共现**、
  主题扶余致密油与主身完全一致 → **并入**（李军辉 20→21 篇）
- 王成门槛外 11 个分身，合作者**部分重叠**（top5 里 1-2 个相同）→ **不并**，标下界
- `A5085046651` 署名仅 `J Li` → **不并**

**宁可保守。** 部分重叠就并，会把同名不同人的产出算进来——
低估是「数字偏小」，错并是「数字指错了人」，性质更严重。

## 门槛外的分身不要硬并

合并到「门槛内」即可，剩下的明确标注为**下界**。

大庆例：王成有 13 个 author.id，门槛内 2 个合并（院署名 2→9 篇、被引 162→222），
**门槛外 11 个未计入**。名单里王成的数字仍标「下界」。

**不要为了数字好看去并门槛外的分身**——合作者证据不足时硬并，会把同名不同人
的产出算进来，性质比低估更严重。

## 证据链格式（必须留）

数据件里每个合并过的条目追加：

```json
{
  "merged_ids": ["A5047240344"],
  "disambig_note": "4 分身；合作者共现郑强/方菊晨/白雪峰；主题同古龙页岩油；院署名一致"
}
```

`merged_ids` 记被吸收的 author.id，`disambig_note` 记判定依据。
**这是可复核的证据链，不是装饰**——别人质疑你的合并时，靠它回查。

## 操作要点

- **本地反查优于网络**：把 works 原始 json 留本地（含完整 authorships），
  反查口径与名单完全一致，不依赖网络
- **姓名归一化用 `isspace()`**：`raw_affiliation_strings` 含 U+00A0 NBSP，
  `.replace(" ", "")` **去不掉且不报错**（见 `openalex-pitfalls.md`）
- **合并后字段口径**：院署名数/被引/年份范围取并集，代表作按标题去重，
  机构证据取并集样本
- **人数同步**：合并 N 组分身，核心人数减 N（大庆：74→71）；
  附录待核实人数同步减（被吸收的分身原本在附录里各占一行）

## 交付时必须写明的三句话

1. 本名单做过 X 组分身合并（列证据表）
2. 未并入的门槛外分身有 Y 个，故 Z 某的数字仍为下界
3. 有 W 个同名分身判为同名不同人（列反证）

## 键口径必须全局统一（2026-09-29 中石化物探院实战，血泪）

这是本链路最容易造成**静默全盘失效**的坑，且不报错、不崩、退出码 0。

### 事故复现

`merges.json` 的组键被写成 `group_key`（**字符多重集**，字序无关）：

```
yangwang  → aaggnnwy
Dingjin Liu → dgiiijlnnu
```

而消费脚本 `apply_merges.py` 用自己的 `norm()`（**有序**小写）去查：

```
yangwang  → yangwang      # 与 aaggnnwy 不匹配
```

结果：**15 组合并决策全部 MISS**。脚本正常退出、日志只写
「跳过 xxx：待并分身均不在核心名单」、校验全绿、退出码 0——
但核心名单里刘定进因此占了两行，没人发现。

### 三条硬纪律

1. **唯一实现处**：键口径只能用 `author_identity.group_key`，
   任何脚本不许在本地重写一份 `norm()`。字序无关 vs 有序，两份实现必然漂移。
2. **零命中即硬失败**：决策表非空而可执行计划为 0 → `sys.exit` 报错。
   「全部跳过」和「本来就没东西可并」必须区分开。
3. **校验器读键要和被校验数据同一把尺子**：
   校验器用有序 `norm()` 比对 `group_key` 键，会得到「0 组未混入核心名单：OK」——
   这是**假通过**，0 组本来就没查成。

### 配套：三种语义不许混在一个字段里

| 字段 | 语义 | 本人是否在核心 |
| --- | --- | --- |
| `merge` | 已判定同一人并合并 | 在（keep） |
| `no_merge` | **只是不合并碎片**，证据不足以并 | **仍在**（keep 凭自己那几篇已达标） |
| `reject_whole_group` | 整组判同名不同人 | **不在** |

2026-09-29 把后两者混在一个 `no_merge` 里，校验器一律按
「判不并 = 不进核心」去查，误报 3 人污染——**是校验器的语义假设错了，不是名单错了**。

> 判据：**问「本人是否被剔除」，不要问「碎片是否被合并」。**

### 配套：校验脚本自身崩了 ≠ 通过

`python make_report.py ... | tail` 取的是 `tail` 的退出码，不是 python 的。
脚本中途 `AttributeError` 崩溃，屏幕上仍显示「全部通过」、`exit=0`。

```python
if __name__ == "__main__":
    try:
        rc = main()
    except Exception:
        traceback.print_exc(); sys.exit(2)   # 崩了就非零，不许走到「全部通过」
    sys.exit(rc or 0)
```

再加一条：**「全部通过」只能在所有校验跑完之后打印**，不能提前。

## 坑：`name:` 合成键的丢弃会在全链路每个消费点复发（2026-09-29）

OpenAlex 未分配 author.id 的作者行走 `name:<归一化名>` 合成键。**任何**下游
脚本用 `is_real_openalex_id()` 过滤 `merged_from`，都会把这些人的真实论文
静默丢掉——同一个 bug 在一条链上踩了两次：

1. `apply_merges.py`：旧代码 `frags = [f for f in frags if not f.startswith("name:")]`，
   理由是「论文已挂主片名下」——经原始缓存证伪（Guanghui Hu 的 W4299444035
   18 引独立院署名论文不在主片里）。丢 1 篇/18 引，产物仍是"合理 JSON"。
2. `l2_extract.py`：修完 #1 后重跑逐篇证据，刘卫华 26 篇 vs roster_merged 27 篇——
   差的正是 `name:liuweihua` 的 W4405468983。过滤发生在
   `ids = [i for i in ... if is_real_openalex_id(i)]` 这一行，与 #1 同构。

**判据**：修一处不够。凡消费 `merged_from` / entity 引用列表的脚本，
全链路 grep `is_real_openalex_id|startswith("name:")`，逐个确认合成键有
独立抓取通道（by_name + author.id 为空 + work 集合去重）。回归测试见
`scripts/test_name_fragment_recompute.py`。
